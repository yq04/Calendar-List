# Kal 范围读取与有界搜索实施记录

> 2026-10-15 的历史实施记录，文中的固定 42 格属于当时版本。当前月历按月份使用 35/42 格，最新功能与支持范围以 [README](../README.md) 和 [v0.1.3 发行说明](RELEASE_NOTES_0.1.3.md) 为准。

日期：2026-10-15。P2 最小前端优化，未构建可执行文件、未启动 Kal/原软件、未修改后端或性能脚本。P0/P1 既有主题行为保持。

## 做了什么

`bridge.rangeEvents(start,end)` 转发 `range_events({start,end})`。月历按 42 格首末日期发一次包含两端的范围读取，替换原先可见矩阵涉及的两到三个月查询；保留 `monthEvents` API 供兼容调用。Mock 增加真实日期、顺序和最多 93 个自然日校验，返回同一来源、日期范围内的原 DayItem 元数据；Preload 同步支持范围读取。

未新增范围或永久月缓存。跨月、显式刷新、已确认写入后重新读取范围；原有刷新/写入失效入口保留为使旧 range/day 返回失效的 `invalidateReads()`。同月选日立即更新选中样式及对应内存草稿，然后独立 `day_events` 查询，以保留日程新鲜性，不重复查询整个月历。`agendaGuard` 丢弃旧日期的迟到结果；完整 render 在等待范围读取前捕获 agenda 序号，避免旧范围返回覆盖切日后刚取得的日程。等待日数据时不预先删除现有编辑节点，内联草稿生命周期沿用 P0。

新增 `ui/src/search-scheduler.js`：110 ms 防抖，最多一个 IPC 在飞，额外只保留最新一个等待词。新词立即使旧回显失效、清除上一组可跳转结果；旧请求自然结束后，只执行已过防抖窗口的最新等待词，避免用大量并发 IPC 掩盖查询成本。关闭、清空及 compositionstart 取消计时器/排队并使旧成功或失败响应失效。程序刷新和写后搜索也检查真实合成状态，不能绕过 IME 守卫。compositionend 重新调度最终词。

Tauri invoke 当前没有本层可调用的中止接口，因此取消意味着取消排队及回显资格，不能谎称已中止后端工作；旧在飞请求完成前不会发第二个搜索。原 `searchGuard` 继续作为显示层第二道序号守卫。

针对性备份：`_backup/ux-search-range-de02939922c94f8aad681fc74d533652`。

## 验证

`ui/_range-selftest.mjs` 对比范围结果与旧月份结果经可见日期过滤后的全字段集合，覆盖邻月首末、跨年、闰年、周起始及 93 天边界/非法日期；验证新 bridge 参数与旧月份 API 仍在。

`ui/_search-scheduler-selftest.mjs` 使用受控 Promise，验证只有 first 与 latest 执行，中间词丢弃，active 最大为 1；旧成功/旧失败不回显、取消等待词不执行，重新打开后最后词能执行。

DOM 检查继续把原 350 ms 可控读延迟施加到 `range_events`，保留快速新增刷新期间不丢草稿和旧提交跨日隔离的回归覆盖。新增启动仅一次范围调用、同月 day-only、迟到 day 返回和搜索延迟/关闭/清空/合成取消检查。本轮 `node tools/ui-check.mjs` 最终 **31/31 通过**，`node ui/_selftest.mjs` **100/100 通过**，新增 range 与 scheduler 两个自检套件均通过。未用 Mock 毫秒数宣称原生性能提升。

## 遗留什么

真实后端 `range_events` 联调、新可执行文件构建和相同环境的前后性能测量由 root 统一执行。本报告不宣称已达到某一毫秒预算，也不把减少 IPC 次数升级为已测加速。Windows 原生 IME、实际多屏 DPI 与生产宿主写入仍沿用既有独立门槛。

## 设计偏差

不新增长期规范化缓存、不新增索引或依赖；保留实时 day 查询而不是把某次绘制的数据当作持续新鲜。搜索请求无法在本层撤销，采用有界串行和结果失效；这会使新词在旧慢请求完成后执行，是避免无界并发的有意取舍。
